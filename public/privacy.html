What you send

Drop sends files and notes between two paired browsers using a WebRTC data channel, encrypted in transit. The recipient chooses whether to accept a file. File integrity is checked before a download is offered. All file extensions and binary contents are accepted within the file-size limit. Files are not scanned for malware and are never automatically previewed, opened or executed. Some filenames are normalized for operating-system compatibility.

Pairing and room information

The pairing server holds random room identifiers, temporary credentials, connection messages and expiry information in memory. It receives network addresses. Rooms last up to two hours and end when a paired device disconnects or you end the room. Invites expire earlier. Approve only the device you intended and compare security codes on both screens.

What remains on your device

This build has no persistent file database or recipient signup. Received files and notes remain in the page’s memory until the room is reset or the page is closed. Downloads you save remain on your device. Clipboard content is not read automatically; copying requires your action. Files and chat are shown in separate tabs. The interface retains up to 40 file activity entries and the latest 200 messages in memory; it is not a permanent chat archive.

The application does not install analytics or advertising trackers, set pairing cookies, or persist chat history in localStorage or IndexedDB. Hosting infrastructure may process request metadata independently. See Cookies & local data for the distinction.

Services involved in a connection

The website is hosted by Vercel. The pairing service runs on Render. Cloudflare provides the public STUN service that helps browsers find a connection. These providers can receive request or network metadata, such as IP addresses and connection times. STUN does not carry your files or notes.

This beta has no TURN relay configured. Files and notes travel directly between paired browsers; some networks cannot connect. A direct connection may reveal your network address to the other device.

The pairing application does not write file contents, notes or room credentials to a persistent database or application log. Providers may retain infrastructure and operational logs under their own policies beyond a room’s lifetime. Room expiry is not a promise that all provider metadata has been deleted.

Your choices and questions

You can decline incoming files, end your room, close the page and remove any downloaded files through your device. Keep invite links private. If you choose Share invite, your operating system and the app you select receive the invitation link; sharing is never automatic. Drop does not provide anonymous networking or a malware guarantee.

Drop is maintained by Pranav Teja. For support, privacy questions or a request about information you have sent us, visit the Contact page. Do not include invite links, private files or security codes.

If you email support, your address and message are handled through Gmail and kept for responding and resolving the request. Do not send files just to ask about a transfer: Drop cannot retrieve files from a closed room. We have not established a fixed support-email retention period; you can ask us to delete correspondence, subject to any applicable retention duties.
